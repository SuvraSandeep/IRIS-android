# Command routing and listening overhead — 11.0.5

Based on main 8bb70b0b (merged 11.0.4).

The loose SMS regex accepted `tell` and `let` before fuzzy contact resolution. A misrecognized information question could therefore resolve to an unrelated contact and enter the SMS permission flow. It now requires an explicit text/message/SMS verb. `tell by the time` and the narrow `tell my the time` variant are recognized as time requests. Message bodies are not rewritten, and recipient/message confirmation and Android permissions remain required. To address someone, use `text mom ...`; `tell mom ...` no longer implicitly chooses SMS.

Continuous audio previously allocated FFT real/imaginary/power arrays every 20 ms. Each DTW comparison also allocated a row for every input frame. Scratch storage now belongs to each frontend instance, and DTW rotates two rows. No global mutable audio scratch is shared. After checking the saved revision, final wake confirmation reuses the armed, isolated profile instead of decrypting and copying it again on the UI thread; model, route and owner checks remain mandatory. Frame normalization, distance formulas, phrase acceptance, model weights and owner thresholds are unchanged. ONNX owner sessions explicitly disable worker spinning between intermittent inferences. See the official runtime guidance: https://onnxruntime.ai/docs/performance/tune-performance/threading.html and Java SessionOptions API.

Sound feedback now passes both captured model vectors to the owner check. Previously the UI dropped the ECAPA vector, so sound feedback on dual-model profiles always failed. Identity centroids and thresholds are not changed by sound feedback; missing either required vector and other speakers remain rejected. The separate rejected-owner correction policy is unchanged.

Validation: the offline regression script includes the reported command and negative cases for message bodies/recipients, reused FFT buffers after noise and silence, streaming matching at varied speed/volume/alignment, negative vetoes and repeated detections. A local before/after comparison against the previous source produced identical features and distance/checksum; a 2,000-iteration synthetic feature+DTW workload allocated 45,744,264 versus 1,440,048 bytes. This desktop microbenchmark is not a phone latency/battery measurement. Android unit/build/lint results are recorded in the PR.

A user-provided encrypted profile was inspected only in private scratch. No profile, password, biometric vectors or per-user metrics are included in this repository. A saved profile can reveal enrollment margins, but contains no failed live audio, microphone history or crash trace. These changes do not establish first-call success, identify every device hang, or replace the acoustic matcher with a neural keyword model. Current training is retained; no forced retraining or silent threshold reduction is included.
